# Threat Model STRIDE

Dokumen ini memuat analisis ancaman STRIDE untuk sistem yang digambarkan pada DFD (Data Flow Diagram) dengan dua trust boundary.

## 1. Referensi elemen DFD

| ID | Jenis | Nama | Keterangan |
|---|---|---|---|
| E1 | External entity | Pengguna | Klien web / mobile, berada di zona tidak tepercaya |
| P1 | Proses | Autentikasi | Login, otorisasi, penerbitan token |
| P2 | Proses | Pengelolaan Data | Pemrosesan data pengguna dan transaksi |
| P3 | Proses | Enkripsi dan Simpan | Enkripsi AES-256 dan pengelolaan kunci |
| D1 | Data store | DB Pengguna | Data pengguna, kata sandi (hash), data sensitif (AES-256) |
| D2 | Data store | Log Audit | Log aktivitas sistem |
| F1 | Data flow | Kredensial login | E1 → P1, dilindungi TLS |
| F2 | Data flow | Token JWT | P1 → E1, dilindungi TLS + tanda tangan |
| F3 | Data flow | Permintaan data transaksi | E1 → P2, dilindungi TLS |
| F4 | Data flow | Data sensitif | P2 → P3, dilindungi AES-256 |
| F5 | Data flow | Tulis/baca database | P3 → D1, dilindungi AES-256 |
| F6 | Data flow | Log aktivitas | P2 → D2, belum dilindungi kriptografi |
| TB1 | Trust boundary | Internet ke zona aplikasi | Memisahkan E1 dari P1, P2, P3 |
| TB2 | Trust boundary | Zona aplikasi ke zona data | Memisahkan P1, P2, P3 dari D1, D2 |

## 2. Ringkasan ancaman

| ID | Kategori STRIDE | Elemen DFD | Aset terdampak | Risiko |
|---|---|---|---|---|
| T01 | Spoofing | E1, F1, P1 | Kredensial dan akun pengguna | Tinggi |
| T02 | Spoofing | F2, P1 | Token sesi (JWT) | Tinggi |
| T03 | Tampering | F3, P2, TB1 | Data transaksi | Tinggi |
| T04 | Tampering | D1, F5, TB2 | Data pengguna di database | Tinggi |
| T05 | Repudiation | P2, F6, D2 | Jejak audit transaksi | Sedang |
| T06 | Repudiation | D2, TB2 | Integritas log audit | Sedang |
| T07 | Information disclosure | F1, F3, TB1 | Kredensial dan data sensitif saat transit | Tinggi |
| T08 | Information disclosure | D1, TB2 | Hash kata sandi dan data sensitif tersimpan | Tinggi |
| T09 | Information disclosure | P3, F4 | Kunci enkripsi | Kritis |
| T10 | Information disclosure | F6, D2 | Data pribadi yang terbawa ke log | Sedang |
| T11 | Denial of service | E1, F1, P1, TB1 | Ketersediaan layanan autentikasi | Tinggi |
| T12 | Denial of service | P3, D1, D2 | Ketersediaan database dan penyimpanan log | Sedang |
| T13 | Elevation of privilege | P2, F3 | Data pengguna lain (otorisasi objek) | Tinggi |
| T14 | Elevation of privilege | P1, F2 | Hak akses admin (klaim peran) | Kritis |

## 3. Detail ancaman

### T01 - Spoofing: pengambilalihan identitas pengguna
- Elemen DFD: E1, F1, P1
- Aset terdampak: kredensial dan akun pengguna
- Skenario: penyerang memakai credential stuffing atau phishing untuk login sebagai pengguna sah melalui F1.
- Mitigasi: autentikasi multi-faktor, rate limiting dan penguncian akun, pemeriksaan kata sandi yang bocor, hashing Argon2/bcrypt dengan salt di D1.

### T02 - Spoofing: token sesi dicuri atau dipalsukan
- Elemen DFD: F2, P1
- Aset terdampak: token sesi (JWT)
- Skenario: token dicuri lewat XSS atau jaringan tidak aman, atau dipalsukan dengan menyalahgunakan algoritma `none` atau kunci yang lemah.
- Mitigasi: kunci algoritma tanda tangan di sisi server (RS256/HS256 dengan kunci kuat), masa berlaku token singkat, cookie `HttpOnly` dan `Secure`, mekanisme revokasi token.

### T03 - Tampering: manipulasi data transaksi saat transit
- Elemen DFD: F3, P2, TB1
- Aset terdampak: data transaksi
- Skenario: penyerang mengubah parameter permintaan (nominal, ID tujuan) lewat man-in-the-middle atau proxy.
- Mitigasi: TLS 1.2 atau lebih baru dengan HSTS, validasi dan rekalkulasi nilai penting di server, tanda tangan atau HMAC pada transaksi bernilai tinggi.

### T04 - Tampering: modifikasi data database lewat injeksi
- Elemen DFD: D1, F5, TB2
- Aset terdampak: data pengguna di database
- Skenario: SQL injection atau akses langsung dengan kredensial database yang bocor mengubah atau menghapus data di D1.
- Mitigasi: query berparameter, prinsip least privilege untuk akun database, pemisahan akun baca dan tulis, firewall internal di TB2, pemeriksaan integritas data.

### T05 - Repudiation: pengguna menyangkal transaksi
- Elemen DFD: P2, F6, D2
- Aset terdampak: jejak audit transaksi
- Skenario: pengguna menyangkal telah melakukan transaksi dan sistem tidak punya bukti yang cukup karena log tidak memuat identitas, waktu, dan hasil aksi.
- Mitigasi: pencatatan wajib untuk aksi sensitif (siapa, apa, kapan, dari mana), sinkronisasi waktu (NTP), tanda tangan digital pada transaksi penting.

### T06 - Repudiation: log audit diubah atau dihapus
- Elemen DFD: D2, TB2
- Aset terdampak: integritas log audit
- Skenario: pihak internal atau penyerang yang menguasai server menghapus atau mengubah log untuk menutupi jejak.
- Mitigasi: penyimpanan log append-only/WORM, hash chain atau HMAC per entri, pengiriman log ke sistem terpisah (SIEM), pemisahan hak akses antara admin sistem dan admin log.

### T07 - Information disclosure: penyadapan data saat transit
- Elemen DFD: F1, F3, TB1
- Aset terdampak: kredensial dan data sensitif saat transit
- Skenario: penyerang di jaringan publik menyadap lalu lintas lewat Wi-Fi palsu atau downgrade protokol ke HTTP.
- Mitigasi: TLS wajib, HSTS dan redirect HTTPS, nonaktifkan protokol dan cipher lemah, certificate pinning pada aplikasi mobile.

### T08 - Information disclosure: kebocoran data tersimpan
- Elemen DFD: D1, TB2
- Aset terdampak: hash kata sandi dan data sensitif tersimpan
- Skenario: dump database, backup yang tidak terenkripsi, atau disk yang dicuri membuka data pengguna.
- Mitigasi: enkripsi AES-256 at rest, hash kata sandi dengan Argon2/bcrypt dan salt, enkripsi backup, pembatasan akses jaringan ke D1.

### T09 - Information disclosure: kunci enkripsi bocor
- Elemen DFD: P3, F4
- Aset terdampak: kunci enkripsi
- Skenario: kunci ditulis langsung di kode, berkas konfigurasi, atau repositori sehingga seluruh enkripsi di D1 dapat dibuka.
- Mitigasi: simpan kunci di KMS/HSM, pisahkan kunci dari data terenkripsi, rotasi kunci berkala, batasi dan catat akses ke kunci.

### T10 - Information disclosure: data sensitif masuk ke log
- Elemen DFD: F6, D2
- Aset terdampak: data pribadi yang terbawa ke log
- Skenario: log aplikasi mencatat kata sandi, token, atau data pribadi. Aliran F6 belum dilindungi kriptografi sehingga isi log dapat dibaca jika D2 bocor.
- Mitigasi: masking dan redaksi data sensitif sebelum dicatat, enkripsi log at rest dan saat transit, pembatasan akses baca ke D2.

### T11 - Denial of service: banjir permintaan login
- Elemen DFD: E1, F1, P1, TB1
- Aset terdampak: ketersediaan layanan autentikasi
- Skenario: penyerang membanjiri P1 dengan permintaan login sehingga pengguna sah tidak bisa masuk.
- Mitigasi: rate limiting per IP dan per akun, WAF, CAPTCHA setelah beberapa kegagalan, auto-scaling dan load balancer.

### T12 - Denial of service: kehabisan sumber daya penyimpanan
- Elemen DFD: P3, D1, D2
- Aset terdampak: ketersediaan database dan penyimpanan log
- Skenario: query berat atau pembanjiran log memenuhi disk dan memperlambat D1, atau proses enkripsi di P3 menghabiskan CPU.
- Mitigasi: batas waktu dan batas ukuran query, kuota penyimpanan dan rotasi log, pemantauan kapasitas dengan peringatan dini.

### T13 - Elevation of privilege: akses data pengguna lain
- Elemen DFD: P2, F3
- Aset terdampak: data pengguna lain (otorisasi objek)
- Skenario: pengguna mengubah ID pada permintaan F3 (IDOR) dan P2 mengembalikan data milik pengguna lain karena tidak memeriksa kepemilikan.
- Mitigasi: pemeriksaan otorisasi per objek di sisi server, penggunaan ID yang tidak mudah ditebak, uji otorisasi otomatis.

### T14 - Elevation of privilege: klaim peran pada token dimanipulasi
- Elemen DFD: P1, F2
- Aset terdampak: hak akses admin (klaim peran)
- Skenario: penyerang mengubah klaim `role` di JWT menjadi admin, atau P2 mempercayai klaim tanpa memverifikasi tanda tangan dan sumber peran.
- Mitigasi: verifikasi tanda tangan di setiap permintaan, ambil peran dari sumber tepercaya di server, prinsip least privilege, pencatatan setiap aksi administratif.

## 4. Catatan

- Aliran F6 (log aktivitas) adalah satu-satunya aliran yang belum diberi perlindungan kriptografi pada DFD. Ini sudah tercermin pada T06 dan T10.
- Tingkat risiko di atas adalah penilaian kualitatif awal (dampak dan kemungkinan). Sesuaikan dengan skema penilaian yang diminta, misalnya DREAD atau matriks risiko.
